# Simplifying Excessive Nesting

Dependent computations often need several intermediate values at once. VibeLang gives them ordinary local names, so sequencing needs no nested callbacks or record of named bindings. In TypeScript Effect code, do notation and generators express the same dependency order.

## Recognizing nesting in dependent pipelines

```vibe
function elapsed<A>(program: () => A) {
  const started = Clock.currentTimeMillis()
  const value = program()
  const finished = Clock.currentTimeMillis()
  Console.log(`completed in ${finished - started} ms`)
  return value
}

function example() {
  return elapsed {
    sleep("40 millis")
    return "complete"
  }
}
```

```text
completed in 40 ms
complete
```

Later statements still see `started` and `value`, with no nested callback to keep each in scope. The callback type leaves its contract inferred, so errors and services from `program` pass through `elapsed`.

## Named bindings with do notation

```vibe
function readInterval() {
  return Effect.Do
    |> Effect.bind(%, "started", () => Clock.currentTimeMillis())
    |> Effect.bind(%, "value") {
      sleep("40 millis")
      return "complete"
    }
    |> Effect.bind(%, "finished", () => Clock.currentTimeMillis())
}
// Returns { started, value, finished }.
```

```text
{"started":0,"value":"complete","finished":40}
```

`Effect.Do` is an Effect value holding an empty record. Each `%` stands where `Effect.bind` expects a program, so the pipe passes the bindings so far by name. Each `Effect.bind` runs its callback and adds the result under a new, unique field name; later callbacks see earlier fields. The style suits maintaining an existing pipeline; local variables are the usual VibeLang spelling.

## Introducing derived values

```vibe
function intervalRecord() {
  return Effect.Do
    |> Effect.bind(%, "started", () => Clock.currentTimeMillis())
    |> Effect.bind(%, "finished") {
      sleep("40 millis")
      return Clock.currentTimeMillis()
    }
    |> Effect.let(%, "millis", ({ started, finished }) => finished - started)
}
```

```text
{"started":0,"finished":40,"millis":40}
```

`Effect.let` adds a field computed by a synchronous, non-failing callback; use `bind` when the field needs Effect work. In an ordinary function both become `const` declarations, and the compiler infers each expression's contract.

## The sequence as ordinary statements

```vibe
function intervalRecord() {
  const started = Clock.currentTimeMillis()
  sleep("40 millis")
  const finished = Clock.currentTimeMillis()
  const millis = finished - started
  return { started, finished, millis }
}
```

```text
{"started":0,"finished":40,"millis":40}
```

This is the VibeLang form of the same sequence. In a TypeScript file, `Effect.gen(function* () { ... })` binds each Effect result with `yield*` to a local name; in a `.vibe` file, ordinary calls already sequence. `function*` declares a value producer, not another syntax for running a single-result Effect.

## Coming from Effect

- `Effect.Do` and named `bind` fields usually become local `const` bindings.
- A derived `Effect.let` field becomes an ordinary expression.
- An `Effect.gen` body becomes a function body, with calls replacing `yield*`.
