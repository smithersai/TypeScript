# VibeLang for Effect users

Keep Effect's runtime, libraries, layers, and error channels; in `.vibe` files, write sequential work as ordinary functions and statements. The [cheat sheet](/vibelang-features/115-cheat-sheet) shows every change beside its Effect code, and the [specification](/spec/000-intro) gives the rules behind each.

```vibe
function greet(name: string) {
  sleep("10 millis")
  const message = `Hello, ${name}`
  Console.log(message)
  return message
}

function main() {
  return retry(greet("Ada"), Schedule.recurs(2))
}
// Output: Hello, Ada
// Output: Hello, Ada
```

Where it stands, `greet("Ada")` runs and returns a string. Passed to `Effect.retry`, whose parameter expects a program, the same call is passed by name, and retry runs it on each attempt. Use `async` and plain `await` only inside a boundary hatch; `await.all`, `await.allSettled`, `await.any`, and `await.race` are VibeLang's concurrent forms.


## Call VibeLang from TypeScript

Compile both files with `vibelang`, rather than ordinary `tsc`. In a `.ts` source, import the relative `.vibe` path **with its extension**:

```vibe
// t5.vibe
export function clampAll(values: ReadonlyArray<number>) {
  return forEach(values, (value) => Math.min(10, Math.max(0, value)))
}
```

```ts
// use.ts
import { Effect } from "effect"
import { clampAll } from "./t5.vibe"

console.log(JSON.stringify(Effect.runSync(clampAll([-2, 4, 15]))))
// Output: [0,4,10]
```

To TypeScript, `clampAll(...)` returns an `Effect.Effect<number[], never, never>`. Run that program at the application boundary: `Effect.runSync` works when execution stays synchronous; `await Effect.runPromise(clampAll(...))` also supports asynchronous work. Import runners from `effect` as above, or `runSync` / `runPromise` from `vibelang-runtime`. Supply any required services with `Effect.provide` before running. A function whose plain return annotation makes it compile to plain JavaScript, such as `function addOne(n: number): number`, returns its value directly and takes no runner. Inside `.vibe`, call the function directly; see [Running Effects](/getting-started/009-running-effects).

For `src/t5.vibe` and `src/use.ts`, keep these settings in `tsconfig.json`:

```json
{
  "compilerOptions": {
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "rootDir": "src",
    "outDir": "dist",
    "rewriteRelativeImportExtensions": true
  },
  "include": ["src/**/*.vibe", "src/**/*.ts"]
}
```

Keep the starter's other compiler options. `include` must cover a standalone `.ts` entry point: a `.ts` file imported by an included file is already part of the project, but an unreferenced `src/use.ts` is otherwise neither built nor typechecked. The current starter includes both `.vibe` and `.ts` files under `src/`. `rewriteRelativeImportExtensions` rewrites `"./t5.vibe"` to `"./t5.js"` in emitted JavaScript. Build, then run the emitted caller:

```sh
bun run build
node dist/use.js
```

Node runs the JavaScript output; importing the `.vibe` source directly with Node does not compile it.

## Translate the idioms

| In Effect TypeScript | In VibeLang |
| --- | --- |
| `Effect.gen(function* () { ... })` | An ordinary function with statements |
| `class NotFound extends Data.TaggedError("NotFound")<{ readonly id: string }> {}` | `error NotFound { id: string }` |
| `const User = Schema.Struct({ id: Schema.String })` and `type User = typeof User.Type` | `schema User { id: string }` |
| `const Role = Schema.Literals(["admin", "member"])` and `type Role = typeof Role.Type` | `schema Role = "admin" \| "member"` |
| `interface Cart { readonly id: string; items: Array<Item> }` | `interface Cart { id: string; mutable items: Array<Item> }` |
| `const x = yield* work()` | `const x = work()` |
| `pipe(x, Effect.map(f), Effect.flatMap(g))` | Bind the result, transform it, call the next function |
| `Option.getOrElse(Option.map(maybe, f), () => 0)` | `maybe.map(f).getOrElse(() => 0)` |
| `pipe(stream, Stream.filter(p), Stream.take(3))` | `stream.filter(p).take(3)` |
| `work().pipe(Effect.retry(policy), Effect.timeout("1 second"))` | `work() \|> retry(%, policy) \|> timeout(%, "1 second")` |
| `Context.Service` | `service Users { find(id: string): User!NotFound }`; call `Users.find(id)` |
| `Layer.effect(Users, Effect.gen(function* () { ... }))` | `Layer.effect(Users) { setup; return { find(id) { ... } } }` |
| `Effect.provide(program, AppLive)` | `provide AppLive { ... }` |
| `Effect.provideService(program, Random.Random, seeded)` | `provide Random = seeded { ... }` |
| `Effect.catchTag(program, "Missing", recover)` | `try { ... } catch (e) { return match (e) { when Missing: ...; default: throw e; } }` |
| `Effect.catch(program, (e) => recover(e))` | `program catch (e) => recover(e)` |
| `Effect.orElseSucceed(program, () => value)` | `program catch value` |
| `Effect.ensuring(program, cleanup)` | `try` / `finally` |
| `Effect.scoped` with `Effect.acquireRelease` | Acquire with `using` in the block that owns the resource; see the [pending-interruption limitation and holder](/resource-management/030-scope#known-limitation-pending-interruption-and-javascript-disposables) |
| `Effect.forkScoped(program)` | `fork work()` for a child owned by the enclosing block; `fork { ... }` forks a block |
| `Fiber.join(fiber)` | `join fiber`; `join [a, b]` joins several and interrupts the rest on a failure |
| `Effect.all([a, b], { concurrency: "unbounded" })` | `await.all [a(), b()]`, like `Promise.all`; `await.all { x: a(), y: b() }` keeps the keys |
| `Effect.all(effects, { concurrency: "unbounded", mode: "result" })` | `await.allSettled [a(), b()]`, with a `Result` for each success or expected failure |
| `Effect.raceFirst(a, b)` | `await.race [a(), b()]`, like `Promise.race`: the first to finish wins |
| `Effect.raceAll([a, b])` | `await.any [a(), b()]`, like `Promise.any`: the first success wins |
| `Effect.forEach(items, f, { concurrency: 8, discard: true })` | `for concurrent(8) (const item of items) f(item)` |
| `Effect.sync(() => render())` | `sync(render())` |
| `Effect.try({ try: () => parse(text), catch: (e) => new BadInput({ e }) })` | `try((text) => parse(text), (e) => new BadInput({ e }), text)` |
| `Effect.tryPromise((signal) => fetchJson(url, signal))` | `try(async (url, signal) => fetchJson(url, signal), url)` |
| `Effect.promise(() => load())` | `sync(async () => load())` |
| `Effect.callback((resume) => …resume(Effect.succeed(x))…)` | `callback((resume) => …resume(x)…)` |
| `Effect.runPromise(program)` in TypeScript | `runPromise(main())` in a `.ts` file or a hatch's body |
| `Stream.fromIterable` or a generator-based source | A producer: `function*` with `yield value` |

`await.allSettled` captures typed failures as `Result.fail` and never fails with a typed error. Defects and interruption propagate exactly as in `Effect.all` with `mode: "result"`.

Use Effect's operators for retries, timeouts, concurrency, and Stream transformations. Statements replace operators that only sequence ordinary work.

## Port code with --fix

Effect declarations and combinator calls ported from TypeScript compile in a `.vibe` file, with warnings EK4830-EK4837 where VibeLang has its own form. `Effect.gen` bodies do not compile there: rewrite them as functions with ordinary calls instead of `yield*`. Run `npx vibelang -p tsconfig.json --fix --noEmit` to rewrite every one whose VibeLang form keeps what the program does, then read the warnings left: each says what its form would change. See [TypeScript-style Effect code](/getting-started/012-devtools#typescript-style-effect-code).

## Calls run; programs stay cold

```vibe
function sequential() {
  const first = greet("Ada")
  const second = greet("Grace")
  return [first, second]
}

function concurrent() {
  return all([greet("Ada"), greet("Grace")], { concurrency: 2 })
}
// Output: Hello, Ada
// Output: Hello, Grace
// Output: Hello, Ada
// Output: Hello, Grace
// Output: [["Hello, Ada","Hello, Grace"],["Hello, Ada","Hello, Grace"]]
```

A call whose result type is Effect runs at that point, except where a parameter expects a program, as in `Effect.retry`, `Effect.timeout`, `fork`, and entries in `Effect.all`: there the call is passed by name and runs when the program runs. A program of several statements is a function with no arguments, `() => { ... }`.

A held Effect value runs when called with no arguments. Data that Effect can also execute, such as `Config` and `Exit`, stays data until explicitly called. A producer call constructs a lazy Stream; see [Producers](/vibelang-features/112-producers).

## Preserve a factory's call-time work

When TypeScript captures configuration before returning an Effect, keep that phase in a function with a declared Effect return and return a parameterless program:

```vibe
export const capture = (input: { mutable value: number }): Effect.Effect<number, never, never> => {
  const snapshot = input.value
  return () => snapshot
}
```

A TypeScript caller can build `capture(input)`, mutate `input`, then run the program, and still get the snapshot. The outer body runs synchronously at the call and can compute or copy plain data; every path returns a program. **Where TypeScript returned Effect.fail(e), write return () => \{ throw e \}**; the outer body never fails, so a throw there is EK2115. Put Effects and service lookups inside the returned program.

A forwarding member keeps its delegate's call phase with `const program: Effect.Effect<number, never, never> = base.read(path); return program`. A const with a declared Effect type holds its initializer in any scope: `const built: Made = make(config)` calls the factory now and runs none of the result. Capture values at the same phase as the TypeScript implementation; keep reads intended for execution inside the returned program.

A synchronous visitor that must return a program keeps its callback type unchanged: return `() => { ... }` from the callback, then run the returned program from effectful code. A discarded `items.map(item => save(item))` still needs `Effect.forEach` or a loop.

VibeLang callers keep the usual rules: `retry(make(config), policy)` calls the factory again each attempt; `const p: Made = make(config); retry(p, policy)` calls it once and retries that program. `Effect.suspend(() => () => 1)` still yields a function value.

## Declare at the module top level

```vibe
// start.vibe
export function main() {
  Console.log("started")
}
// node start.js runs main
// Output: started
```

Declare functions, services, schemas, and layers at module scope, but run no program there: `const answer = Effect.succeed(1)` is EK1001. An explicitly Effect-typed const, such as `const answer: Effect.Effect<number, never, never> = Effect.succeed(1)`, stores a cold program and runs nothing at import. Export a parameterless `main` instead: the module runs it with `NodeRuntime.runMain` when node starts the module, and importing it runs nothing. To provide layers or runner options, call the runner at the top level yourself, `NodeRuntime.runMain(() => Effect.provide(() => main(), AppLive))`; the module then runs only that.

Every export of Effect's root, including `Console`, `Clock`, `Option`, `Schedule`, and `Stream`, is in scope without an import, along with VibeLang's runtime helpers. JavaScript globals such as `Array` keep their meaning; import Effect's conflicting modules under another name. Subpaths such as `effect/http` still need imports.

## Keep platform work in Effect

```vibe
function reportTime() {
  const now = Clock.currentTimeMillis()
  Console.log(now)
  return now
}
// Output: 123
// Output: 123
```

`console.log`, `fetch`, timers, `Date.now()`, and `node:*` calls are errors in `.vibe` (EK4402, EK4403). Effect has a service for each, and the error names it, its import, and the layer that provides it. Use the prelude's `Console`, `Clock`, `sleep`, and `Config`. Import a platform service by name and call it. The file that exports `main` names its platform once, and the entry provides that platform's layer to `main`:

```vibe
// notes.vibe
import "vibelang/platform/node"
import { FileSystem } from "effect/FileSystem"
import { Path } from "effect/Path"

export function main() {
  using directory = FileSystem.makeTempDirectoryScoped()
  const file = Path.join(directory, "note.txt")
  FileSystem.writeFileString(file, "saved")
  Console.log(FileSystem.readFileString(file))
}
// Output: saved
```

`"vibelang/platform/node"` provides `NodeServices.layer`, which holds `FileSystem`, `Path`, `Crypto`, `Stdio`, `Terminal`, and `ChildProcessSpawner`; `"vibelang/platform/bun"` provides `BunServices.layer`. `HttpClient` comes from `effect/http`; provide `FetchHttpClient.layer` inside `main`. [The platform introduction](/platform/105-introduction) lists the service for each common Node.js and web call. Don't wrap a platform API that Effect covers in a hatch, a `module`, or a `.ts` adapter. You can import a Node function or pass it as a value; running it directly is a platform API error. [Building an HTTP API](/vibelang-features/113-building-an-http-api) passes `createServer` to a server layer.

Inside an Effect function, a plain function from your `.ts` code or a foreign package needs a boundary hatch, `try((text) => parse(text), text)` or `sync(render())`, or a trusted declaration. A platform API that Effect lacks, such as `os.hostname()`, is often one of VibeLang's [experimental platform APIs](/vibelang-features/118-experimental-platform-apis): `Process.hostname()`. A hatch's first argument is plain, self-contained TypeScript: `async`, `await`, `throw`, and platform APIs keep their JavaScript meaning there, and `runPromise` or `runFork` leads back in. It reads a `.vibe` value, such as `text`, only as an input: an argument after the function, bound to its first parameter. To trust workspace or other TypeScript packages, set `"vibelang": { "trustedPackages": ["@acme/*"] }` at the top level of `tsconfig.json`. Exceptions from a matching package's synchronous plain calls are defects, its Effects run, and EK4401 does not fire. `trusted(impl, [Errors])` declares a function's expected failures. Effect's own packages are trusted, including `assert` and `expect` re-exported by `@effect/vitest`.

## Trace and debug calls

Run emitted JavaScript with `node --enable-source-maps dist/main.js` and enable `"sourceMap": true` in `compilerOptions`. Source maps preserve `.vibe` locations. Function tracing defaults to `"none"`, so defects can show only one stack frame. Set `"vibelang": { "tracing": "exported" }` at the top level of `tsconfig.json` and rebuild to trace exported functions. Use `"all"` to trace local functions too.

Use `withSpan("checkout") { ... }` for a named operation, as you would use `Effect.withSpan` in TypeScript. Function spans supply the logical caller context that source maps alone cannot add, and add runtime work. If the default Node runner prints only an error message, use the [TypeScript debugging entry](/getting-started/012-devtools#debug-stack-traces) to print the rejected error's `stack`.

## Runtime cost

These are single-machine observations from the 0.0.9 alpha review on Linux x64, Node 26 and Effect 4.0.6. They are not a performance guarantee. The benchmark timed sequential loops with `Clock.currentTimeMillis`, with 200,000 calls for the success-only comparison and 1,000,000 for recovery and plain functions. The step increments a number and fails every 250,000th value; recovery resets it to zero. The success-only loop ends before that failure.

| Loop | Observed time |
| --- | ---: |
| 200,000 Effect-contracted VibeLang calls without `catch` | 550 to 610 ms, about 2.9 µs per call |
| 200,000 `Effect.fn` generator calls | 860 to 1,200 ms |
| 1,000,000 `step(n) catch 0` expressions | 3.0 to 3.8 s |
| 1,000,000 `Effect.succeed`/`Effect.fail` steps with `Effect.orElseSucceed` | About 0.33 s |
| 1,000,000 plain-function calls | About 3 ms |

Effect-contracted calls were in the same order of cost as `Effect.fn` generators. The `catch` loop cost more than the hand-written `Effect.orElseSucceed` loop. A function that compiles to plain JavaScript adds no Effect wrapper. Measure your own workload, including tracing, before choosing a boundary for a hot loop.

## Catch expected failures only

```vibe
error Missing { id: string }

function lookup(id: string) {
  if (id !== "ada") throw new Missing({ id })
  return { id, name: "Ada" }
}

function displayName(id: string) {
  try {
    return lookup(id).name
  } catch (error) {
    return `Unknown user: ${error.id}`
  }
}
// Output: ["Ada","Unknown user: missing"]
```

Inside an Effect function, `throw` adds an expected failure to the function's error channel, and `catch` receives it. Defects and interruption bypass `catch`; `finally` still runs. `Effect.orDie(() => work())` promotes an expected failure to a defect; to inspect defects, use Effect's cause APIs at a boundary.

Contracts remain `Effect<A, E, R>`, or `A!E!R` for short, and most functions infer them. In the shorthand, `A!E` checks the success and error channels and infers dependencies from the body; an empty slot is `never`. In `Effect<A, E, R>`, a type argument left out is `never`, as in TypeScript; write `infer E` or `infer R` to infer one.

For the feature with no direct Effect equivalent, see [Control operations and handlers](/vibelang-features/111-control-operations-and-handlers).
