# Control operations and handlers

A control operation lets a handler decide how the caller continues. Use one when a dependency must pause a program, answer a request, or end it early.

## Declare and perform an operation

```vibe
// approval.vibe
export error ReviewBusy { request: string }

export control Approval {
  approve(request: string): boolean!ReviewBusy
}

export function release(version: string) {
  if (!Approval.approve(`deploy ${version} to staging`)) return "staging declined"
  if (!Approval.approve(`deploy ${version} to production`)) return "production declined"
  return `released ${version}`
}
// string!ReviewBusy!Approval
// Output: released v1
```

`Approval.approve` returns a boolean at the call, and `Approval` stays in the program's requirements until a handler answers it. Each abstract operation writes its contract, as a service member does.

`Control`, `handle`, `resume`, `resumeWith`, and `abandon` are globals in `.vibe` files.

## Run one program with two policies

```vibe
// policies.vibe
import { Approval, release } from "./approval.vibe"

export function autoApprove(version: string) {
  try {
    return release(version)
  } handle Approval.approve(_request) {
    resume(true)
  }
}

export function scriptedReview(version: string, decisions: ReadonlyArray<boolean>) {
  let next = 0
  try {
    return release(version)
  } handle Approval.approve(_request) {
    const approved = decisions[next] ?? false
    next++
    resume(approved)
  }
}

export function comparePolicies() {
  return [autoApprove("v1"), scriptedReview("v1", [true, false])]
  // ["released v1", "production declined"]
}
// Output: ["released v1","production declined"]
```

A `handle` clause after a try block names an operation, `Approval.approve`, and parameters typed like the operation's. The clause runs each time the try block performs the operation.

`resume(true)` continues the try block with `true` as the operation's result. The handler is deep: the next approval request reaches the same clause. A clause that ends with `resume` runs in constant stack space, however many times the block performs the operation.

A `return` in the try block or a clause returns from the enclosing function; `break` and `continue` leave its loops. One statement can handle several controls, and answers every operation of each: give each operation a clause (EK2108).

A clause can work after `resume`: the try block runs to its end, then the clause continues, then the statement ends the way the try block did. A `return` in the try block takes effect after the clause, as a pending `return` waits for a `finally` block. That `resume` returns the value the statement ends with: what the try block returns, or `undefined` when it ends without returning. If the block performs an operation again first, a clause that returns ends the statement with its value instead, so `resume`'s type includes what every clause returns.

Every `resume` of the statement has one answer type H. The compiler computes H once from the try block's and clauses' returns, leaving out clause returns computed from a non-tail `resume` result, then checks those returns against H. A return outside H is EK2119, an error. Write the enclosing function's success type to cover those answers; H then uses that written type. In either case, H also includes `undefined` when the try block, or a clause that has not resumed, can finish without returning a value.

A continuation can be consumed once; the runtime rejects a second resume. Call `resume`, `resumeWith`, and `abandon` in the clause's own code, not in a nested function.

## Stop and clean up

```vibe
// stopping.vibe
import { Approval } from "./approval.vibe"

function deployment() {
  try {
    Approval.approve("deploy to production")
    return "deployed"
  } finally {
    Console.log("deployment hold released")
  }
}

export function stopDeployment() {
  try {
    return deployment()
  } handle Approval.approve(_request) {
    abandon()
    Console.log("cleanup finished")
    return "cancelled"
  }
}
// Output: deployment hold released
// Output: cleanup finished
// Output: cancelled
```

`abandon()` runs the try block's cleanup before the clause continues: it skips the block's `catch` blocks and runs its `finally` blocks and resource releases. Cleanup failures still fail the operation.

A clause that ends without resuming also stops the try block and cleans it up; then the statement completes, and the function continues after it. Use `abandon()` when cleanup must finish before the clause's next statement.

## Resume with an expected failure

```vibe
// busy.vibe
import { Approval, ReviewBusy } from "./approval.vibe"

export function busyReviewer() {
  try {
    return Approval.approve("deploy now") ? "approved" : "declined"
  } handle Approval.approve(request) {
    resumeWith(() => { throw new ReviewBusy({ request }) })
  } catch (error) {
    return `review unavailable: ${error.request}`
  }
}
// Output: review unavailable: deploy now
```

`resumeWith` runs its program at the original operation call, inside the try block. The program can raise only the operation's declared errors and must need no services: read services in the clause first, then capture their values in the program.

Catch clauses and a `finally` block can follow the handle clauses and cover both the try block and the clauses, so here the catch clause sees the `ReviewBusy` the operation call raised.

## Use handle as an expression

The statement is short for the `handle` function, which takes a program and returns its result:

```vibe
// expression.vibe
import { Approval, release } from "./approval.vibe"

export function countReleased(versions: ReadonlyArray<string>) {
  let released = 0
  for (const version of versions) {
    const outcome = handle(() => release(version), Approval, {
      approve(_request, k) {
        return resume(k, true)
      }
    })
    if (outcome.startsWith("released")) released++
  }
  return released
}
// Output: 2
```

`handle(program, Control, clauses, onReturn?)` takes a program, the control class, and a clause for every operation. A clause receives the operation's arguments, then `k`, the continuation that `resume(k, value)`, `resumeWith(k, program)`, and `abandon(k)` take. `resume` returns the resumed program's result, or what a clause returns when the program performs an operation again first. The optional fourth argument, `onReturn`, transforms normal returns. `resume` is typed with the program's own result, or `never` when `onReturn` is supplied, so reading its result where a clause can return another type is EK2110. Keep `k` inside its clause; never save or return it.

## Keep handlers on the executing fiber

```vibe
// concurrent.vibe
import { Approval } from "./approval.vibe"

export function approveAll(requests: ReadonlyArray<string>) {
  return forEach(requests, (request) => {
    try {
      return Approval.approve(request)
    } handle Approval.approve(_request) {
      resume(true)
    }
  }, { concurrency: 4 })
}
// Output: [true,true]
```

Handle the operation inside each concurrent branch. A handler on the parent fiber cannot answer a child fiber's control operations.

| Diagnostic | Meaning | Fix |
| --- | --- | --- |
| EK2005 | A `resumeWith` program needs a service or raises an undeclared error | Read the service in the clause; raise only the operation's declared errors |
| EK2107 | A handle clause names an operation of a non-control, such as a service | Provide a service with a layer or a `provide` block |
| EK2108 | A handle statement leaves an operation of its control without a clause, or gives one two clauses | Add the missing clause, or remove the second |
| EK2110 | A `handle(...)` clause reads a `resume`'s result, but a clause or `onReturn` can produce a value of another type | Return the program's type from every clause, or return `resume`'s result unread |
| EK2119 | A clause returns a value computed from `resume`'s result outside the handler's answer type | Write the function's success type to include it |
| EK4201 | Work sent to another fiber still requires a control operation | Handle it inside the branch, or run sequentially where the combinator supports it |
| EK4202 | A TypeScript function's declared requirements include a control operation | Write it in VibeLang, or handle the operation in the TypeScript implementation |

Stream operators also run a producer on its own fiber, so handle its control requirements inside the producer before passing it to one. See [Producers](/vibelang-features/112-producers).
